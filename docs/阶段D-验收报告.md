## 2. 三个关键设计

### 2.1 校验比生成更重要

模型返回的 JSON 不可全信。`validate_questions` 逐项检查，**不合格整体拒绝**：

- 题目数量是否等于要求（不能少给）；
- 题型是否与要求一致（要单选却给了判断）；
- 单选必须 4 个选项、判断必须 2 个；
- 选项 key 不能重复；
- 答案必须落在选项 key 里；
- 题干不能过短。

任一不合格 → 重试一次 → 仍不合格则明确报错，**绝不把半成品写进数据库**。
如果只是"丢掉坏题"，数量就对不上，用户会以为系统少出题了。

### 2.2 判分绝不交给模型

正确答案是结构化字段，比对由 Python 完成：

```python
is_correct = bool(user_answer) and user_answer == correct
```

模型只负责"出题 + 写解析"。这样判分可复现、可测试，也不受模型随机性影响。

### 2.3 意图路由：规则优先，省一次调用

| 层级 | 触发 | 例子 |
|---|---|---|
| 规则 | 命中关键词 | "帮我出 3 道单选题" → `generate_quiz`，count=3 |
| 轻量 LLM | 规则未命中 | "我最近学得怎么样" → `analyze_mistakes` |
| 兜底 | 模型分类失败 | 退回 `knowledge_qa`，不报错 |

规则命中时**不调用模型**（测试里断言 `llm.calls == []`），既省钱又降延迟。

工具参数一律在 Python 侧校验：`count` 必须 1–10、`question_type` 只能是
single/judge、课程必须存在、query 不能为空——模型传错就返回结构化错误，页面不会崩。

## 3. 双答题模式接口（本次特别要求）

答题页不认识任何具体玩法，只认 `modes.base.QuizMode`：

```python
answers = mode.render(ctx)   # {question_id: 选项 key}；None 表示还没提交
result  = grade_batch(settings, answers)
```

- 新增玩法 = 在 `modes/` 加一个文件 + 在注册表加一行，**页面与判分都不用改**；
- 题库、判分、`quiz_attempts` 表全部复用，玩法只影响作答界面；
- `GameMode.available = False` 时，页面自动展示"待接入"占位与候选玩法，
  而不是给一个点不动的按钮。

## 4. 真实运行结果

### 出题（真实模型，topic = 频域滤波，3 道单选）

```
1. 在频域滤波中，理想低通滤波器在截止频率处突变，最可能导致下列哪种现象？
   A 振铃效应  B 块效应  C 椒盐噪声  D 多分辨率分解   答案 A
   解析：理想低通在截止频率处突变会产生振铃；巴特沃斯过渡平滑，振铃明显减轻。

2. 关于频谱中心化后的二维傅里叶频谱，下列描述正确的是？
   A 低频位于四周，高频位于中心      B 低频位于中心，高频位于四周
   C 低频和高频都集中在中心          D 频谱中不区分低频与高频   答案 B

3. 若要在频域处理中突出图像边缘以用于锐化，适合采用下列哪种滤波？
   A 低通  B 高通  C 均值  D 中值   答案 B
```

三道题全部可由课件第 4 页直接判定，没有引入外部知识，解析与原文一致。

## 6. 踩到并修掉的问题

| 问题 | 原因 | 处理 |
|---|---|---|
| "帮我出 5 道单选题" 识别不出意图 | 规则写成 `出.{0,4}题`，中间"5 道单选"占 6 个字符 | 放宽到 `出.{0,8}题`，并补 `来.{0,6}道` 覆盖"来三道" |
| 出题 Prompt 里没有资料 | 出题上下文只取了 topic 检索，未指定 topic 时为空 | 改为 `index.sample(6)` 全课程取样，测试断言 Prompt 含"直方图" |

## 7. 已知限制

- 游戏模式未实现（按需求留接口）；
- 出题质量依赖资料片段长度：片段过短时容易出"常识题"；
- 判断题的选项固定为"正确/错误"，模型若给别的措辞会被拒（有测试保证）；
- 意图路由对"帮我总结第三章"这类既非问答也非出题的说法会归到知识问答。
