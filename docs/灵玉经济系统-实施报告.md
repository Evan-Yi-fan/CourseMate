# 灵玉秘境（游戏模式）实施报告

> 日期：2026-11-03　按反馈修正：品字堆叠、卡槽合成规则、棋盘升阶链。

## 1. 为什么推倒重做

上一版的问题：游戏塞在答题页的模式选择里，只有"战力数字比大小"，没有棋盘、没有卡牌堆叠、
没有合成、没有妖怪行进——不是游戏。本次重做后：

- **页面独立**：`pages/5_灵玉秘境.py`，不再出现在「智能试题」的模式列表里；
- **玩法完整**：堆叠卡池 → 三消合成 → 5×5 布阵 → 妖怪行进 → 塔防拦截 → 神兽系统。

## 2. 架构：Python 管两端，游戏跑在 iframe 里

```
pages/5_灵玉秘境.py
  ├─ 战前答题（Python）      QuizService 出题 → grade_batch 判分 → RewardCalculator 算灵玉
  ├─ 注入灵玉与配置           game/view.py 把 economy_config 打包进 window.CM_CONFIG
  └─ 游戏内核（iframe）       game/web/{index.html, game.css, game.js} 自包含，无外部依赖
       └─ 关卡结束 → 把战报写回 ?game_result=... → Python 读取并展示
```

**为什么游戏不写在 Python 里**：拖拽合成、卡片上下错位遮挡、妖怪逐帧移动，
这三样 Streamlit 原生组件都做不到（按钮不能拖动，也不能做遮罩层级）。
把交互层做成自包含前端，是唯一能真正实现这些玩法的路子。

**边界很清楚**：灵玉的**来源**（答题奖励）仍由服务端计算，页面无法伪造；
游戏内的**消费**在浏览器端扣减，其价格与上限由 Python 侧的配置注入，保证两边同一套数值。

## 3. 玩法逐条对照

| 你的要求 | 实现 |
|---|---|
| 下方方格内卡片合成文字 | 卡池 6 列，每列 2~4 层卡片 |
| 普通汉字 / 铲子 / 异兽神兽字 | 三类卡：普通字（五行 + 山川风雷云雨日月）、铲子 ⛏、神兽字（青/龙/白/虎） |
| **上下错位堆叠**，先点上面的才能点下面的，但不完全遮挡 | 每层下移 12px 错位排布；只有最上层可点（有 hover 抬起效果），下层变暗但**字仍可见** |
| 点普通卡进上层卡槽 | 5 格卡槽（可扩到 7），同字自动叠在同一格，显示 ×N |
| 三个一样的字合成并填入 5×5 方格 | 集满 3 个自动合成（火→焱、水→淼、金→鑫、木→森、土→垚），自动落到棋盘空格 |
| **自动合成 + 手动拖动合成** | 自动：满 3 立即合成；手动：把一张卡拖到另一张同字卡上，数量相加，够 3 同样触发 |
| 棋盘初始格子 + 局内闯关/铲子解锁 | 初始 5 格；铲子卡解锁 1 格；每守完一波自动再解锁 1 格 |
| 妖怪沿固定路线移动，到尽头扣皇后血，等级不同扣血不同 | 绕棋盘一圈的折线路径；妖兵 -1、妖将 -2、妖王 -3；血量 10 |
| 文字只有功能/攻击方式差异，无相克 | 每个基础字只有"伤害/射程/攻速/附加效果（减速、溅射）"不同，**没有属性克制表**；阶数只提升数值 |
| 波次结束刷新下方卡片、不刷新上方棋盘 | 波次结束只重建卡池；棋盘阵容原样保留（有测试断言） |
| 阵容随时可调，包括闯关时 | 棋盘上的字可拖动交换、可点击撤回卡槽；战斗中同样可操作 |
| 两个神兽棋盘（仅存放，不参战） | 右栏两块神兽盘，各 3 格，只用于摆字 |
| 按正确顺序摆放激活神兽 | 青龙＝青→龙，白虎＝白→虎；顺序错不激活 |
| 激活后仍可拆解 | 点击已激活的神兽即拆解 |
| 三阶字拖到激活的神兽上吞噬、概率升星 | 三阶字（焱/淼/垚…）拖到已激活神兽字上：消耗一张，55% 升 1 星（上限 5 星） |

> **神兽格部分待确认**：目前实现是"每个神兽两个槽，按顺序放对即激活"。你提到这块解释起来比较麻烦，
> 而我又读不到原游戏正文（见下），所以先保留现状，等你给出规则再改。

神兽增益：青龙 +20% 全体攻击，白虎 +15% 全体攻速，每颗星再叠加 15%。

## 6. 原游戏规则（已抓到原文）

原游戏是 **《万妖图录卷》**。网页抓取工具被 DNS 拦截，改用 PowerShell 直连抓到了正文：

| 原文 | 说明 |
|---|---|
| 集齐三个相同文字，即可自动上阵参与防守 | 三合 → 该字上阵 |
| 金木水火土五行文字是防守单位，妖魔沿外围道路进攻 | 防守单位＝汉字，路径在外围 |
| 三合可以合成"炎""焱"等威力更强大的单字 | 升阶字形 |
| 五行各有叠字形态，火系炎焱、木系林森逐级进阶 | 升阶链 |
| 凑齐特殊文字可以组成"青龙""白虎"等神兽名 | 神兽由字组成 |
| **神兽单位如青龙横跨两个格子** | 神兽是 2 格单位 |
| 叠层牌堆配三合融合玩法 | 卡池是叠层 |
| 别让手里的字牌闲置在**暂存格**里 | 卡槽的正式叫法 |

出处：
- https://www.18183.com/zhxz/9051749.html
- https://m.18183.com/zhxz/9055675.html
- https://ku.18183.com/wytlj/

据此修正了三处：
1. "皇后" → **人皇**（原文"拼异兽，救人皇"）；
2. "卡槽" → **暂存格**；
3. 神兽不再只是旁边的小面板：凑齐 青+龙 / 白+虎 后，
   神兽作为**横跨两格**的单位直接上阵（随机找一对相邻空格），右侧格被占据、不可再放字；
   攻击判定取两格中点，攻击范围与伤害单独配置。

## 7. 已知限制

1. **游戏期间不要动页面其他控件**：Streamlit 重跑会重载 iframe，本局进度重置。
   这是 iframe 方案的固有代价；演示时进入游戏后就不要再点页面。
2. **局内消费在浏览器结算**：灵玉总额由服务端给出，但商店扣减发生在 JS，
   若要严格服务端记账，需要把每次购买上报回来（本次未做）。
3. **战斗是简化塔防**：没有弹道飞行物、没有技能动画，攻击用冷却条 + 数值结算体现。
4. **关卡进度未落库**：本局结果回写到页面展示，但没有写新的数据表；
   答题记录仍然正常入库。
5. **难度未经过真人试玩**：波次强度、怪物血量都在 `economy_config.GAME_SETTINGS`
   与 `game.js` 的 `ENEMY` 表里，随时可调。

## 7. 怎么玩

```powershell
streamlit run app.py
```

进入「灵玉秘境」→ 生成 5 道题 → 答题拿灵玉 → 进入游戏：
点顶部卡 → 三消合成 → 布局 → 出战 → 守三波。
